# 文档规范

## 语言与事实

- 使用简体中文；字段、类名、接口路径和命令保留原文。
- 区分“已实现”“已知限制”“待确认”，不得把规划写成现状。
- 当前代码、路由和迁移优先于帮助页；帮助页优先于过时说明。
- 不复制密码哈希、Token、身份证完整样例、银行卡号或生产配置。

## 公共文档

公共规则放在 `docs/share/`：

```text
docs/share/
├── 项目概览.md
├── 开发规范.md
├── 接口规范.md
└── 文档规范.md
```

跨功能变化修改公共文档；只影响一个模块的内容放在功能目录。

## 功能文档结构

```text
docs/功能名称/
├── README.md
├── 用户说明.md
├── 业务流程图解.md
├── 业务数据模型.md
└── 业务变更增量.md
```

### README.md

说明功能目标、使用角色、业务边界、页面入口、接口、权限、依赖和已知限制。

### 用户说明.md

从业务用户视角说明使用前提、操作步骤、结果核对、异常排查和角色差异。不得用用户说明替代精确接口或数据模型。

### 业务流程图解.md

至少包含总流程、关键流程、状态流转、异常分支和校验点。优先使用 Mermaid；节点文字包含标点时使用引号。

### 业务数据模型.md

前端项目至少记录页面模型、筛选参数、提交参数、枚举、敏感字段和与后端表的映射；数据库字段的最终定义以配套后端同名文档为准。

### 业务变更增量.md

按日期倒序追加：

```markdown
## YYYY-MM-DD

- 新增：……
- 调整：……
- 已知限制：……
- 待确认：……
```

不伪造历史，不覆盖旧记录。本次首次整理统一记为“现状基线建立”。

## 接口与字段引用

- 接口写明方法、路径、核心参数、返回和权限。
- 状态、金额公式和匹配键必须能追溯到代码。
- 表格字段过多时可以按业务分组，但不能遗漏关键字段或把前端显示名误写成数据库字段名。
- 相对链接从当前文档位置验证可达。

## 同步要求

- 前后端功能变化时同步更新两个项目对应文档。
- 用户操作变化时检查后端 `helps/` 是否需要另行更新；没有授权时只记录待同步项。
- 文档完成后执行 `codegraph sync`，确保后续 Agent 能检索最新规范。
