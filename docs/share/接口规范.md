# 接口规范

## 适用范围

本文记录当前前端实际需要兼容的后端协议。由于项目存在历史接口差异，不能直接套用其他项目的成功码或字段命名。

## 认证

- 登录：`POST /api/login`，JSON 请求体包含 `username`、`password`。
- 登录成功后保存 JWT，后续请求携带 `Authorization: Bearer <token>`。
- 获取当前用户：`GET /api/user/info`。
- 修改本人密码：`POST /api/user/change-password`。
- 退出：前端清理本地 Token；后端同时提供 `POST /api/logout`。
- `code = 401` 或 HTTP 401 视为登录失效。

不得在 URL、日志、文档或错误提示中输出 Token。

## 当前响应结构

业务接口主要有两种结构：

```json
{
  "code": 0,
  "msg": "获取成功",
  "data": {}
}
```

```json
{
  "code": 0,
  "message": "获取成功",
  "data": {}
}
```

任务中心接口当前成功返回 `code = 200`。因此前端规则是：

- 普通业务接口按 `code === 0` 判断成功。
- `/api/tasks*` 按现有实现兼容 `code === 200`。
- 提示优先读取 `msg`，为空时读取 `message`。
- 不得把其他项目的成功码写入或用于本项目。

新增接口建议统一为 `code + msg + data` 且成功码使用 `0`；统一改造属于独立任务，不能在普通功能变更中顺手调整历史接口。

## 分页

| 模块 | 请求参数 | 返回字段 |
|---|---|---|
| 系统用户 | `page`, `limit` | `list`, `total`, `page`, `limit` |
| 未救助/应补应退/通知 | `page`, `page_size`，部分兼容 `limit` | `list`, `total`, `page`, `page_size` |
| 参保台账/配置/批次 | `page`, `page_size` | `list`, `total`, `page`, `page_size` |
| 任务中心 | `page`, `page_size` | `list`, `total`, `page`, `page_size` |

页码最小为 1；页面切换每页条数时回到合理页码。不能假设所有接口接受同一分页字段。

## 筛选与排序

- GET 列表通过 `params` 传筛选条件。
- 数组筛选以对应接口现有实现为准，不在页面自行序列化成未经约定的格式。
- 台账远程排序传稳定字段和方向，只允许后端白名单字段。
- 镇街账号的数据范围不由前端参数决定，后端根据当前用户强制追加范围条件。

## CSV 上传

```text
Content-Type: multipart/form-data
file: 单个 .csv 文件
year / period / settlement_period: 按接口要求
```

- 当前只支持 `.csv`，不接受 XLS/XLSX。
- 后端自动识别 UTF-8、GBK、GB18030。
- 上传成功通常返回任务 UUID，不代表导入完成。
- 同类任务存在业务锁；重复提交可能被拒绝。

## 异步任务

任务状态：

| 状态 | 含义 |
|---|---|
| `pending` | 等待执行 |
| `processing` | 执行中 |
| `completed` | 已完成 |
| `failed` | 失败，可查看安全的失败原因 |
| `cancelled` | 已取消 |

任务常用字段：`uuid`、`title`、`progress`、`status`、`has_file`、`file_size`、`failure_reason`、`created_at`、`updated_at`。文件下载通过 `/api/download?uuid=<任务UUID>` 中转。

## 错误处理

- 参数或业务错误通常为 `400`，未登录为 `401`，无权限为 `403`，不存在为 `404`，系统异常为 `500`。
- 当前部分错误只返回 `msg` 或 `message`，页面必须安全回退到通用中文提示。
- 不向用户展示 PHP 堆栈、SQL、服务器路径、密钥或完整上游响应。
- 接口失败时不得继续显示成功 Toast，也不得根据本地推测更新业务状态。
