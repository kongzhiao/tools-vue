# 未救助台账用户说明

## 使用前准备

1. 在镇街管理确认名称、编码以及镇街账号绑定正确。
2. 在重大疾病编码维护需要核对的有效编码。
3. 准备符合模板的 CSV；不要上传 XLS/XLSX。
4. 确认清算期，提交任务后到任务中心查看最终结果。

## 未救助明细

1. 选择清算期，导入附件1《未救助明细》。
2. 核对总数、进入报销金额和“无救助金额/拟通知1/拟通知2”分布。
3. 导入附件2《救助对象名单》，按身份证补齐镇街、村社和身份。
4. 打开筛查规则，先核对首项“门诊重大疾病匹配”，再核对其余保留/剔除口径，保存后执行筛查。
5. 抽查金额小于等于300元的记录未命中首项；金额大于300元且命中首项的记录默认应未剔除并跳过后续规则。
6. 抽查已剔除记录的筛查命中规则和备注。
7. 按当前筛选导出未剔除明细，交线下继续核对。

附件1同一清算期已有相同序号时更新原记录；没有序号的行会跳过。

## 应补应退明细

1. 选择清算期，导入附件4《应补应退明细》。
2. 导入附件2补齐镇街、村社、身份和匹配状态。
3. 在应补应退自己的筛查配置中核对首项规则并执行筛查；仅金额大于300元的记录参与首项匹配，命中并默认保留后不再由正负抵消或医疗救助金额大于0等后续规则剔除。
4. 导出当前筛选下未剔除数据继续核对。

附件4没有序号时系统按数据行生成序号。正负抵消只成对剔除，多出的单条记录保留。

## 下放通知

1. 管理员把线下确认需要通知的数据导入“下放通知”。
2. 核对待下放数量和镇街匹配；未匹配镇街的数据不能下放。
3. 管理员按镇街批量下放；尚未接收的数据可以撤销下放。
4. 镇街账号确认接收后，处理本镇街已接收/已通知数据。
5. 线下通知群众后标记“已通知”，必要时可撤销回“已接收”。
6. 镇街回填联系人、电话、开户行、户名、银行账号和备注。
7. 管理员填写管理员备注，按实际拨付结果标记已报销或恢复未报销。
8. 按当前筛选导出通知明细。

## 状态说明

| 场景 | 状态变化 |
|---|---|
| 导入通知明细 | 待下放 |
| 管理员下放 | 待下放 → 已下放 |
| 镇街接收 | 已下放 → 已接收 |
| 标记通知 | 已接收 → 已通知 |
| 撤销通知 | 已通知 → 已接收 |
| 撤销下放 | 已下放 → 待下放，仅限未接收 |
| 标记报销 | 未报销 → 已报销并记录时间 |

## 常见排查

- 镇街为空：检查附件2/通知文件的镇街名称或编码与镇街管理配置。
- 身份为空：检查清算期、身份证和身份列表头。
- 筛查后被剔除：查看筛查命中规则和系统备注；若命中重大疾病首项，检查当前台账处理方式是否被设为“剔除”，修改后重新执行筛查。
- 拟通知2异常增多：核对进入报销金额；重大疾病首项仅应匹配金额大于300元的记录，更新规则后需重新执行筛查刷新旧结果。
- 镇街看不到通知：确认已下放、已接收、账号镇街绑定和清算期。
- 导出数量不同：确认导出时筛选条件、剔除状态和镇街范围。
