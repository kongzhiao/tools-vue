# 未救助台账

## 功能目标

将医保业务 CSV 转为可筛选、匹配、筛查、核对和导出的未救助排查台账，并把最终需要联系群众的数据转入独立的下放通知流程。

## 功能组成

| 页面 | 路由 | 职责 |
|---|---|---|
| 未救助明细 | `/unrescued/records` | 附件1、附件2、独立筛查、统计、筛选、导出 |
| 应补应退明细 | `/unrescued/refund-records` | 附件4、附件2、独立专项筛查、统计、筛选、导出 |
| 下放通知 | `/unrescued/notice-records` | 通知明细导入、下放、接收、通知、反馈、报销标记、导出 |
| 重大疾病编码 | `/unrescued/disease-configs` | 编码增删改查和 CSV 导入 |

未救助明细和应补应退明细只形成排查结果，不直接办理镇街通知；通知流程统一在“下放通知”。

## 使用角色

- 管理员：维护基础数据，导入、筛查、导出，管理下放通知。
- 线下核对人员：核对导出结果并形成通知明细。
- 镇街账号：仅处理本镇街已下放通知，执行接收、通知和反馈。
- 系统/任务中心：异步执行导入、筛查和导出。

## 核心规则

- 所有操作先确认清算期，标准格式为 `YYYYMM`。
- 导入仅支持 CSV，编码自动识别 UTF-8、GBK/GB18030。
- 附件1与附件4按“清算期 + 序号”新增或更新。
- 附件2按“清算期 + 身份证号”补齐镇街、村社、身份和匹配状态。
- 筛查只标记结果，不删除原始记录；未救助与应补应退分别保存规则配置。
- 第一项“门诊重大疾病匹配”默认启用，但仅进入报销金额 `>300` 的记录参与匹配；医疗类别需命中配置，病种编码需精确命中指定编码或启用的重大疾病编码库。
- 状态由金额分档决定，重大疾病规则不覆盖状态；命中后默认保留并跳过后续规则，也可在当前台账单独配置为剔除。
- 未救助进入报销金额：政策范围费用减统筹、大额和大病报销。
- 应补应退进入报销金额还需减医疗救助和渝快保报销。
- 金额 `<=0` 为无救助金额，`(0,300]` 为拟通知1，`>300` 为拟通知2。

## 主要接口

接口统一前缀 `/api/unrescued`：

- `/records`：列表、统计、附件1/2导入、筛查配置/执行/状态、导出、详情。
- `/refund-records`：列表、统计、附件4/2导入、筛查配置/执行/状态、导出。
- `/notice-records`：列表、统计、导入、下放/撤销、接收、通知/撤销、反馈、备注、报销、导出。
- `/disease-configs`：列表、新增、编辑、删除、导入。

## 权限边界

权限按“未救助明细”“应补应退明细”“下放通知”“重大疾病编码”分别控制查看、导入、筛查、下放、回填、备注、报销标记和导出。兼容原因权限标识仍可保留 wash 命名。镇街账号的数据范围由后端根据 `town_id` 强制限制。

## 已知实现事实

- `RecordController` 仍保留旧的直接下放/接收等方法，但当前公开路由未注册这些方法；实际通知流程以 `/notice-records` 为准。
- 筛查规则可以编辑和保存；必须至少启用一条规则才能执行。
- 列显示和固定设置保存在本地浏览器，属于界面偏好，不改变导出范围。
