# 未救助台账业务数据模型（前端）

数据库字段、类型、默认值和索引以配套后端同名文档为准。本文件记录页面使用的视图模型。

## 公共列表模型

未救助明细和应补应退共用以下主要字段：

| 字段 | 类型 | 页面含义 | 边界/默认 |
|---|---|---|---|
| `id` | `number` | 记录主键 | 后端生成 |
| `settlement_period` | `string` | 清算期 | `YYYYMM` |
| `sequence_no` | `string` | 文件序号 | 附件1必有；附件4可按行生成 |
| `name` | `string?` | 姓名 | 可空 |
| `id_card` | `string?` | 身份证号 | 敏感字段，不持久化 |
| `town_id` | `number` | 镇街ID | 未匹配为 0 |
| `street_town` | `string?` | 镇街名称 | 附件2匹配 |
| `village` | `string?` | 村社 | 可空 |
| `priority_identity` | `string?` | 对象类别/身份 | 可空 |
| `match_status` | `string` | 匹配状态 | 未匹配/已匹配 |
| `medical_category` | `string?` | 医疗类别 | 可筛选 |
| `disease_code/name` | `string?` | 疾病编码/名称 | 支持关键词 |
| `hospital_name/code` | `string?` | 医疗机构 | 应补应退无机构编码字段 |
| `admission_date` | `string?` | 入院日期 | 可空 |
| `discharge_date` | `string?` | 出院日期 | 可空 |
| `settlement_time` | `string?` | 结算时间 | 可空 |
| `total_fee` | `string` | 总费用 | 两位小数，默认 0 |
| `policy_fee` | `string` | 政策范围费用 | 两位小数，默认 0 |
| `pool_fund_pay` | `string` | 统筹报销 | 两位小数 |
| `large_amount_pay` | `string` | 大额报销 | 两位小数 |
| `serious_illness_pay` | `string` | 大病报销 | 两位小数 |
| `calc_reimbursement_amount` | `string` | 进入报销金额 | 后端计算 |
| `status` | `string` | 排查状态 | 无救助金额/拟通知1/拟通知2等 |
| `exclude_status` | `string` | 筛查结果 | 未剔除/已剔除 |
| `exclude_rule_code` | `string?` | 筛查命中规则 | 普通保留记录可空；优先保留记录记录规则编码 |
| `remark` | `string?` | 系统备注 | 最长以后端为准 |

未救助明细额外展示四类已使用救助金额；应补应退额外展示医疗救助、渝快保、个人账户和个人现金支付金额。

## 通知明细模型

通知明细复用人员、就医和金额字段，并增加：

| 字段 | 类型 | 含义 | 可见性 |
|---|---|---|---|
| `status` | `string` | 待下放/已下放/已接收/已通知 | 全部 |
| `reimbursement_status` | `string` | 未报销/已报销 | 全部 |
| `system_remark` | `string?` | 导入或系统备注 | 全部 |
| `contact_name` | `string?` | 联系人 | 镇街可编辑 |
| `contact_phone` | `string?` | 联系电话 | 敏感，镇街可编辑 |
| `bank_name` | `string?` | 开户行 | 敏感业务信息 |
| `bank_account_name` | `string?` | 户名 | 敏感业务信息 |
| `bank_account_no` | `string?` | 银行账号 | 高敏感，不本地存储 |
| `town_remark` | `string?` | 镇街备注 | 镇街可编辑 |
| `admin_remark` | `string?` | 管理员备注 | 镇街页面隐藏 |
| `distributed_at` | `string?` | 下放时间 | 状态时间 |
| `received_at` | `string?` | 接收时间 | 状态时间 |
| `notified_at` | `string?` | 通知时间 | 状态时间 |
| `reimbursed_at` | `string?` | 报销时间 | 状态时间 |

## 筛选参数

- 清算期：`settlement_period`。
- 人员关键词：`keyword`，匹配姓名、身份证或序号。
- 镇街、状态、匹配状态、剔除状态、报销状态。
- 医疗类别、身份类别、疾病编码/名称、机构名称、规则编码、备注。
- 通知页面另含联系方式、管理员/镇街备注等实际页面筛选字段。

## 筛查规则模型

```ts
type WashRule = {
  code: string;
  name: string;
  field: string;
  action: 'keep' | 'exclude';
  operator: string;
  values?: string[];
  medical_categories?: string[];
  disease_codes?: string[];
  value?: string;
  compare_field?: string;
  remark?: string;
  enabled: boolean;
};
```

规则保存后才作为执行基线；页面编辑但未保存的值不得被描述为已生效。

`outpatient_major_disease` 是规范化后的首项复合规则：固定前置条件为 `calc_reimbursement_amount > 300`，`medical_categories` 默认“门诊慢特病、造口袋门诊”，`disease_codes` 默认 `M00500`。金额状态由后端分档，规则命中不覆盖 `status`；页面不读取或展示重大疾病库数量，只说明后端自动精确匹配启用项。未救助与应补应退页面分别调用各自保存接口，不共享编辑状态。

## 异步任务提交

导入使用 `FormData`：`file` 加 `settlement_period`。筛查、导出返回任务 UUID；页面只展示任务状态，最终文件与失败原因来自任务中心。兼容原因服务函数和接口路径仍使用 wash 命名。
